🧪 헬퍼 만들기 실습

게임 목록

브라우저 게임 헬퍼가 어떻게 돌아가는지, 그리고 운영자는 어떻게 잡아내는지 우리 게임에서 직접 해 봅니다. 이 게임 전용이고, 다른 사람들과 하는 실제 게임에서는 쓰지 않습니다. 게임 메뉴의 '헬퍼'로 고르면 같은 스크립트가 공개적으로(이름 앞 🧪) 붙고, 아래 북마크로 붙이면 몰래 붙인 셈이라 감지기가 잡는지 볼 수 있어요. 감지 결과는 관리자만 봅니다(게임 화면 위 '관리자').

1. 헬퍼 켜기 (PC)

아래 보라색 버튼을 브라우저 북마크바로 끌어다 놓으세요. 지렁이 대결 화면에서 그 북마크를 누르면 헬퍼가 페이지에 주입되고 오른쪽 위에 패널이 뜹니다.

🧪 지렁이 헬퍼

북마크바가 안 보이면 Ctrl+Shift+B. 끌어 놓기가 안 되면: 지렁이 대결 화면에서 F12 → Console에 아래 한 줄을 붙여 넣고 Enter.


  


  

    
2. 헬퍼는 이렇게 생겼다 (helper.js)

    

      
층이 헬퍼실제 헬퍼들

      
① 읽기페이지 변수 window.game에서 지렁이·먹이·내 위치를 읽고, B 방식 관찰값(16방향 × 먹이·몸·벽)을 직접 계산게임 자바스크립트가 들고 있는 전역 변수를 읽음(옛 slither 봇), 통신 메시지 해석, 화면 픽셀 분석

      
② 판단셀프플레이로 학습한 신경망이 6개 행동 중 하나대부분 규칙(위험 원 안에 몸이 들어오면 반대로, 먹이 덩어리 쪽으로)

      
③ 조작마우스 이벤트 넣기: 가짜 PointerEvent를 캔버스에 보냄
게임 변수 직접 바꾸기: game.input.target을 고침		마우스 이벤트 만들기, 또는 게임의 '마우스 좌표' 전역 변수를 직접 고침

      
그리기게임 캔버스 위에 투명 캔버스를 하나 더 얹어 레이더·화살표줌아웃, 레이더, 미니맵 등

    

  


  

    
3. 감지기는 이렇게 잡는다 (game.js의 AC)

    

      
신호무엇을 보나점수

      
가짜 입력스크립트가 만든 이벤트는 isTrusted=false. 브라우저가 붙이는 표시라 웹 페이지에서는 위조 불가40

      
입력 변조마우스 이벤트가 없었는데 목표 좌표가 바뀜 → 변수를 직접 고친 것35

      
주입 흔적처음에 없던 스크립트·캔버스가 페이지에 생김 (MutationObserver)20

      
반응 속도정면에 위험이 나타난 순간부터 반대로 틀기까지. 사람은 보통 0.2초 이상25

      
입력 규칙성마우스 이벤트 간격의 변동. 사람 손은 들쭉날쭉, 타이머는 일정15

      
완벽한 회피위험 장면 10번 이상 중 95% 이상을 피함10

    

    
60점 이상 = 헬퍼 의심 높음, 25점 이상 = 주의. 실제 서비스는 이 판단을 서버에서 하고(클라이언트 코드는 헬퍼가 고칠 수 있으니까), 여러 판의 기록을 모아 봅니다.

  


  

    
4. 실습 순서

    
    
      
  1. 혼자 연습에서 그냥 몇 판 → 화면 위 내 감지기(또는 관리자 패널)로 내 손의 점수(0~10점대)와 반응 속도를 확인
    2. 
      
  2. 헬퍼 켜기 → 레이더·화살표만 → 감지기에 주입 흔적이 바로 잡히는지
    3. 
      
  3. "위험할 때만 대신 피하기" + 마우스 이벤트 → 가짜 입력으로 즉시 걸림
    4. 
      
  4. 조작 방식을 게임 변수 직접 바꾸기로 → 가짜 입력은 피하지만 입력 변조로 걸림
    5. 
      
  5. 사람처럼 위장까지 켜기 → 반응 속도·규칙성 신호는 피하는지, 그래도 남는 신호는 무엇인지
    6. 
      
  6. 자동 조종으로 학습된 AI ×5와 대결 → 내 손과 길이·죽음 비교
    7. 
      
  7. (도전) 감지기를 더 똑똑하게: 예를 들어 "위험 장면에서만 유난히 정확함"을 잡는 신호를 game.js에 추가
    8.
