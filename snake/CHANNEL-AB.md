# 채널 A/B 실측 — 어떤 방식이 제일 "문제없이" 돌아가는가

측정일 2026-10-30 · 실제 slither.io (headless Chrome 1000×700, 사용자 크롬 불간섭) · 페이즈당 20초

## 2. 조향 유효성 캘리브레이션 (`calib.js`, `S.decide`=상수)

```
AIM  0.000 → eang  0.000   (24표본, 오차 0.000)
AIM  1.571 → eang  1.571   (오차 0.000)
AIM  3.142 → eang  3.142   (오차 0.000)
AIM -1.571 → eang -1.571   (오차 0.000)
```
→ 네 사분면 모두 부호·스케일 오차 0. `aim = atan2(ym, xm)` 그대로. **세 채널 전부 실제로 조향됨.**

## 3. 판정

**페이지 안에서 잡히는가 (관측자 = 사이트 스크립트/확장)**

- `var` — 이벤트 0회인데 `xm`이 524번 바뀜. 이벤트 없이 입력 상태가 변하는 건 정상 브라우저에서 불가능. **단일 신호로 즉시 검출.** 학습·실험용으로만.
- `event` — 이벤트는 있지만 `isTrusted=false` 303/303. **100% 검출.**
- `cdp` — 이벤트 전부 신뢰됨. 잔여 흔적은 궤적 통계뿐: 17회/s의 낮은 레이트(사람 60Hz 대비 1/4)와 57±12.6ms의 거친 주기.
- `cdpH` — 60Hz, 16.7±1.3ms. 사람 마우스(60Hz, sd 3~6ms)와 사실상 동일 대역. 남는 차이는 "완벽히 규칙적"이라는 점인데, CDP 왕복 자체 흔들림으로 sd가 2.4ms까지 벌어짐 → 추가 지터 없이도 사람 범위 안.

**네트워크에서 잡히는가 (관측자 = 서버)**

네 채널 모두 서버가 받는 건 **각도 바이트 8~12회/s** 하나뿐. 채널 간 차이 없음(`Δangle` 분포만 소폭). 즉 **서버는 채널을 구분할 수 없다**. 실제 방어선은 프로토콜이 아니라 세션 수준(세션 지속시간·IP당 세션 수·점수 곡선)이다.

**결론 — 실사용 기본값은 `cdp`(정확히는 `cdpH` 페이싱)**

1. `cdp`/`cdpH` = 신뢰 입력 + 사람 레이트. 검출 표면이 "궤적 통계"만 남는 유일한 경로.
2. `var`/`event` = 성능은 동급이지만 흔적이 이진(있음/없음)이라 **비교 실험·학습 전용**.
3. 성능 차이는 채널이 아니라 `decide` 품질 문제 — 20초 내 사망 2건은 조향 방식과 무관(같은 두뇌로 var/cdpH는 생존).

## 4. 이번 측정에서 고친 버그

- `var` 무효 원인: 번들이 `if (want_e && ctm - last_e_mtm > 33)`일 때만 `atan2(ym,xm)` 소비 → `window.want_e = true` 필수. 수정 후 캘리브레이션 통과.
- `S.decide` 재정의가 무시됨: 틱 루프가 지역 함수 `decide`를 직접 호출 → `S.decide(...)`로 교체(두뇌 교체 실험 경로 확보).
- `event` 모드 y축 부호 반전(`-sin` → `+sin`).

⚠ slither.io 약관은 봇·자동화를 금지합니다. 위 측정은 본인 확인 하의 관찰/학습용이며, 대량 자동 플레이에 쓰지 않습니다.
