# 헬퍼 자체 시험 결과 (2026-10-29)

환경: 로컬 정적 서버 `http://127.0.0.1:8771/snake/` + 헤드리스 Chrome 1000×700,
하네스 `scratch/pptr/snake_review.js`(모드별 프리셋 주입 → 40초 관측 → `#myAc` 얼럿으로 감지 점수 수집).

## 입력 채널이 점수를 결정한다 (핵심)

`steer()`에 `how:"trusted"` 추가 — 헬퍼는 `window.__helperCmd={aim,boost}`만 publish하고,
마우스는 밖에서 CDP `Input.dispatchMouseEvent`로 움직인다. 화면 y가 아래로 증가하므로
목표 좌표는 `x=500+cos(aim)*250`, `y=350-sin(aim)*250`.

| 채널 | 변조(35) | 가짜입력(40) | 주입(20) | 합계 |
|---|---|---|---|---|
| 게임 변수 직접 (`var`) | 35 | 0 | 20 | 55 |
| 페이지 내부 이벤트 (`event`) | 0 | 40 | 20 | 60~85 |
| CDP 신뢰 입력 (`trusted`) | **0** | **0** | 20 | **20** |
| `trusted` + 선언 | 0 | 0 | 면제 | **0** |

즉 "안 걸리는 방향"은 타이밍 튜닝이 아니라 **입력 채널 교체**다. 대가는 루프 주기만큼의
지연(40초에 300회 = 평균 133ms)인데, 위장 지연(140~260ms)이 이미 그보다 커서
성능은 `var`와 같았다(89.5 vs 88.4). 마우스 간격 지터를 `20 + rand*140`으로 넓혀야
"간격 규칙적" 10점이 꺼진다(0.18 → 1.65).


## 읽을 것 3가지

1. **위장은 성능을 실제로 깎는다.** 128.2 → 평균 80.1(3회), 3회 중 1회 사망.
   비용은 거의 전부 `lag`(조향 지연)에서 나온다. `jitter`만으로는 125.3으로 손실이 2% 수준.
   지연 중 대기 비율 33~46%(744틱 중 345틱) — 그 시간만큼 뱀이 직진한다.

2. **위장하지 않으면 오히려 더 들킨다.** `nohuman`이 70점인 이유는
   조향 변경 간격 변동계수 0.09(임계 0.25 미만) → "기계적으로 규칙적" 15점.
   `lag`/`jitter`는 1.0~1.2로 통과. 즉 50ms 고정 틱이 가장 큰 지문이었다.

3. **`event` 모드는 최악(85점).** `isTrusted=false` 433번(40점) + 주입 20점 +
   반응 78ms(25점). 이벤트 주입 경로는 지연을 안 걸어서 반응 지연 신호까지 맞는다.
   `var` 경로는 반응 217~287ms → 통과.

## 패치 검증

- `__snakeHelper.state()` — 정상. `ticks/waited/delay/tickGap/aimGap/declared` 전부 반환.
- 선언 면제 — 메뉴에서 헬퍼 켜면 `declared:true`, 주입 20점 면제 → **55 → 35**.
- 반응 지연 신호 — 표본 3회 조건 완화 후 실제로 발화(event 78ms 적발, var 287ms 통과).
- 조향 간격 신호 — `G.input.aim` 변화 시각을 직접 재도록 바꿔 `how:"var"` 경로도 측정됨.
- 지표 버그 1건 수정: `met.aims`에 절대 시각을 쌓아 평균이 32,725ms로 나오던 것 → 간격으로 변경.

## 남은 것

- 지연 모델 조정 여지: 지금은 방향 전환 순간에만 140~260ms. 87~92가 천장이므로
  지연을 줄이면 성능↑·감지 유지 여부 확인 필요.
- 반응 지연 신호의 표본 부족(30~40초에 위험 에피소드 1~9회) → 임계값보다 **관측 시간**이 문제.
- `NET.report` 로컬 403 → 기록 탭 누적 비교는 여전히 불가(얼럿 경로로 대체 중).
