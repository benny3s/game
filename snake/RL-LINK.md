## 2. 인풋 파라미터 (66차원)

`N_SECT=16` (섹터 폭 22.5°), `VIEW=15` (관측 거리, 클론 단위), `L_MIN=6`.

섹터 k (0~15) 중심각 = `heading + (k+0.5)/16 · 2π`

| 인덱스 | 정의 | 범위 |
|---|---|---|
| `o[4k]` | `1 − min(먹이거리)/VIEW` (섹터 내 먹이 없으면 0) | 0~1 |
| `o[4k+1]` | `min(섹터 내 먹이 수 / 8, 1)` | 0~1 |
| `o[4k+2]` | `1 − min(적 몸통점 거리 − 내 반지름)/VIEW` | 0~1 |
| `o[4k+3]` | `1 − min(섹터 방향 벽까지 거리)/VIEW` | 0~1 |
| `o[64]` | `min(length/100, 1)` | 0~1 |
| `o[65]` | `1 if length > L_MIN+1` = 부스트 가능 여부 | 0/1 |

내 몸통은 관측에서 **제외**(`v[..., 내 슬롯] = False`). 먹이는 `N_NORM=400 + N_DROP=400` 슬롯을 매 틱 재계산.

## 3. 아웃풋 파라미터 (6차원)

| a | 회전 `a%3−1` | 부스트 `a//3` |
|---|---|---|
| 0 / 1 / 2 | −1 / 0 / +1 | 0 |
| 3 / 4 / 5 | −1 / 0 / +1 | 1 |

- 선택 = **argmax** (정책 logits 6개). 학습 시 확률 샘플링, 배포 시 argmax.
- 부스트는 `length > L_MIN+1`일 때만 유효, 부스트 시 길이 0.1/스텝 감소 + 0.5마다 꼬리에 먹이 흘림.
- 속도 `SPEED=0.5`, `BOOST=1.0` (클론 단위/스텝).
- 회전량 = `turn_rate(length) = 0.25·(0.35 + 0.65·(1−x)²)`, `x = clamp((length−10)/250, 0, 1)`. 길수록 둔해짐(최대 0.25 → 최소 0.0875 rad/스텝).

## 6. slither.io 어댑터 (`slither-brain.js`)

`window.slither / slithers / foods / grd / flux_grd`에서 66차원을 재구성 → 순전파 → argmax → `W.xm/ym` + `W.want_e=true`(`var` 모드).

클론과 slither.io의 스케일 차이(실측):

| 항목 | 클론 | slither.io |
|---|---|---|
| 아레나 반지름 | 60 | `flux_grd` ≈ 14,187 (`grd` = 32,550 중심) |
| 전체 먹이 | 800 슬롯 | 실측 406개 |
| 반경 150px 내 먹이 | – | **1** |
| 반경 300 / 450 / 900px | – | 20 / 50 / 177 |
| 내 몸 반지름(`sc=1`) | ~0.6 클론단위 | 27px |

**스케일 k 보정**: VIEW(15 클론단위) 안에 클론과 비슷한 먹이 수(~112개)가 들어오려면 반경 ≈700px → **k ≈ 47**. 같은 k에서 몸 반지름 27px → 0.57 클론단위 = 클론의 초기 몸 두께(0.6)와 일치. 즉 먹이 밀도와 몸 두께라는 독립적인 두 조건이 같은 k로 수렴 → 임의값 아님.

보정 이력(초기 버전의 버그 2개):
1. 스텝당 회전 0.6rad → **0.25·(0.35+0.65(1−x)²)** 로 수정 (env2 실제식).
2. 결정 주기 50ms → **72ms** (k=47에서 클론 1스텝 0.5단위 ≈ 5.4px/프레임 × 4.3프레임).
3. 내 몸통 제외(학습과 동일) / `S.selfBody=true`면 포함(분포 밖이지만 자기충돌 방지용).

- 행동 분포: trained는 사실상 `a=3 / a=5` 교대(−1/+1 회전)만 사용 → 6차원 중 3개만 실사용, 직진은 0회전(a=1/4) 미사용.

## 7-1. 네이티브 환경(클론) 성능 — 전이 손실 없는 순수 모델 성능

`brainbench.js` (로컬 8771 static clone, headless, 2초 간격 샘플, `n` = 샘플 수):

| 두뇌 | 40s maxLen | 40s eaten | 90s maxLen | 90s eaten | 사망(90s) |
|---|---|---|---|---|---|
| untrained | 30.9 | 27.5 | 41.2 | 34.5 | 1 (≈32s) |
| easy | 90.0 | 127 | – | – | 1 |
| mid | 96.2 | 136.5 | 219.8 | 306 | 1 (≈78s) |
| **trained** | **103.5** | **143** | **316.6** | **415** | **0** |

- 순서가 학습 순서와 정확히 단조: untrained < easy < mid < trained.
- trained는 90초 동안 먹이 415개(4.6개/초), 길이 10 → 316.6. mid는 78초에 죽고 219.8에서 멈춤.
- 40초 구간 성장률: trained 2.34/s, mid 2.15/s, untrained 0.51/s.
- 즉 **모델 자체는 정상적으로 학습됨**. slither.io에서 성능이 떨어지는 건 모델 문제가 아니라 §6의 도메인 차이(밀도·자기 몸통·적 밀도) 때문.
