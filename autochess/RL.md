# 베니체스 (autochess) — 강화학습 인터페이스

오토체스의 **경제 · 레벨 · 상점 · 공유 풀 · 연승연패 · 체력**은 실제 규칙대로 시뮬레이션합니다.
배치, 시너지, 증강은 없습니다. 전투는 보드 힘(코스트 × 성급 + 아이템)을 넣은 Bradley–Terry 승률로 결과를 정합니다.
따라서 이 환경에서 배우는 것은 **언제 레벨을 올리고, 언제 리롤하고, 언제 모을지**입니다.

규약은 `onecard/RL.md`와 같습니다. 행동 수는 고정이고, `legalMask`는 `Uint8Array`, `obs`는 `Float32Array`를 씁니다. `step`은 순수 함수이며, 난수는 상태 안의 시드(`s.rng`)로만 만듭니다.

## 규칙 두 벌

| id | 이름 | 인원 | 체력 | 최대 레벨 | 유닛 | 출처 |
|---|---|---|---|---|---|---|
| `A` | 베니 오리지널 | 6 | 60 | 9 | 자체 36종 (`ROSTER_A`) | 자체 설계 |
| `B` | TFT 경제 미러 | 8 | 100 | 10 | 65종(이름 없이 `3코 #5`처럼 번호로 표시) | Set 18 숫자 |

규칙 B의 숫자 중 `[공식]`은 rrtft Set18 표(상점 확률, 풀 크기, XP)와 tftcodex rules(골드, 이자, 연승, 판매가)를 대조한 값입니다.
`[근사]`는 공개 수치가 없어 직접 정한 값으로, 전투 힘, 피해, PvE, 회전목마가 여기에 해당합니다. 각 항목의 표시는 `core.js`의 `RULES_B` 주석에 있습니다.

## API (`require('./core.js')` 또는 브라우저 `AutoChess`)

```js
const C = require('./core.js');
let s = C.create({ rules: 'B', seed: 42, players: 8 });
while (s.phase === 'plan') {
  const p = s.turn;                 // 지금 행동할 자리
  const mask = C.legalMask(s);      // Uint8Array(17)
  const o = C.obsF32(s, p);         // Float32Array(OBS_LEN = 103)
  const a = policy(o, mask);
  ({ state: s } = C.step(s, a));    // 원본은 그대로 두고 새 상태를 돌려줌
}
C.reward(s, p);                     // 1등 +1 … 꼴등 -1
```

- 계획 단계에서는 **자리 순서대로** 한 명씩 행동합니다. 공유 풀이 있어 동시에 행동할 수 없기 때문입니다. 시작 자리는 라운드마다 한 칸씩 돌아갑니다.
- `A_END`를 고르면 다음 사람에게 차례가 넘어갑니다. 마지막 사람까지 끝나면 전투가 진행되고 다음 라운드의 수입, XP, 상점이 자동으로 들어옵니다.
- 학습용 관찰은 반드시 `obs`/`obsF32`만 사용하세요. 화면이나 디버그용으로 상태를 볼 때는 `view(s, p)`를 쓰면 남의 상점과 난수 시드가 가려집니다.
- 같은 시드와 같은 행동열이면 결과도 같습니다. `hash(s)`로 확인할 수 있습니다.

## 행동 (N_ACTIONS = 17)

| 번호 | 상수 | 뜻 | 할 수 있는 조건 |
|---|---|---|---|
| 0–4 | `A_BUY + i` | 상점 i번 칸 사기 | 골드 ≥ 코스트, 그리고 자리가 있거나 사는 즉시 3개가 합쳐질 때 |
| 5 | `A_ROLL` | 새로고침 | 골드 ≥ 2 |
| 6 | `A_XP` | 경험치 4 사기 | 골드 ≥ 4이고 최대 레벨 미만 |
| 7 | `A_END` | 이번 라운드 준비 끝 | 항상 가능 |
| 8–16 | `A_SELL + j` | 벤치 j번 팔기 | 벤치에 유닛이 있을 때 |

- 유닛 목록은 항상 힘 순으로 정렬됩니다. 앞에서부터 `레벨`개가 보드, 나머지가 벤치입니다. 따라서 배치 행동은 따로 없습니다.
- 한 사람이 한 라운드에 할 수 있는 행동은 `MAX_ACTS = 60`번까지입니다. 넘으면 `A_END`만 가능합니다.

## 관찰 (OBS_LEN = 103, push 순서 그대로)

| 칸 | 개수 | 내용 |
|---|---|---|
| 0 | 1 | 스테이지 / 8 |
| 1 | 1 | 라운드 / 스테이지당 라운드 수 |
| 2 | 1 | 레벨 / 최대 레벨 |
| 3 | 1 | 현재 XP / 다음 레벨 필요 XP (최대 레벨이면 1) |
| 4 | 1 | min(골드, 100) / 100 |
| 5 | 1 | (골드 mod 10) / 10 — 다음 이자 구간까지의 위치 |
| 6 | 1 | 이자 / 이자 상한 |
| 7 | 1 | 체력 / 시작 체력 |
| 8 | 1 | 연승(+)·연패(−) / 10, ±10에서 자름 |
| 9 | 1 | 살아 있는 인원 / 전체 인원 |
| 10 | 1 | min(내 힘 / 60, 2) |
| 11 | 1 | 내 힘 / 상대 평균 힘 (÷3, 3에서 자름) |
| 12 | 1 | 회전목마 라운드면 1 |
| 13 | 1 | PvE 라운드면 1 |
| 14 | 1 | 벤치 수 / 벤치 칸 수 |
| 15 | 1 | 보드 수 / 최대 레벨 |
| 16 | 1 | min(아이템, 20) / 20 |
| 17 | 1 | 이번 라운드 행동 수 / 60 |
| 18 | 1 | 지난 라운드 수 / 60 |
| 19 | 1 | 규칙 B면 1 |
| 20–59 | 5 × 8 | 상점 칸마다 `[비었나, 코스트 원핫 5, 같은 1성 보유 수/2, 사면 합쳐지나]` |
| 60–74 | 15 | 내 유닛 개수: (코스트-1)×3 + (성급-1) 칸, ÷9 |
| 75–102 | 7 × 4 | 상대(체력 높은 순) `[살아 있음, 체력/시작 체력, 레벨/최대, 힘/내 힘 ÷3]`. 탈락했거나 자리가 없으면 0 |

길이 = `20 + 5×8 + 15 + 7×4 = 103`. 규칙 A(6명)도 상대 블록은 7칸 고정이고 남는 칸은 0입니다.

## 보상

- 판이 끝났을 때만 0이 아닌 값이 나옵니다. `reward(s, p) = 1 − 2·(등수 − 1)/(인원 − 1)`이므로 1등은 +1, 꼴등은 −1입니다.
- 탈락한 순간 등수가 정해집니다. 같은 라운드에 여러 명이 탈락하면 남은 체력이 더 낮은 사람이 더 낮은 등수를 받습니다.

## 상대 봇 (`ai.js`, 브라우저 전역 `AutoChessAI`)

| 스타일 | 운영 |
|---|---|
| `econ` | 50골드를 모으면서 표준 레벨을 따름. 4-1에서 롤다운 |
| `fast8` | 4스테이지에 8레벨, 30골드 유지 |
| `reroll` | 낮은 레벨에서 50골드 위의 이자분만 리롤 (3~5스테이지) |
| `greedy` | 모으지 않고 바로 씀 |
| `random` | 할 수 있는 행동 중 무작위 (`A_END`는 1/4 확률) |

`AutoChessAI.playout({ rules, seed, seats: ['econ', fn, …] })`으로 한 판을 끝까지 진행합니다. 자리에는 스타일 이름 대신 `(s, rand) => 행동` 함수를 넣을 수 있습니다.

## 학습 계획

1. 기준선: 스타일 봇 5종이 서로 붙은 리그에서 평균 등수를 측정합니다.
2. PPO 셀프플레이: 정책 1개와 과거 정책들, 스타일 봇을 섞어 상대로 씁니다. 행동 마스크를 적용한 소프트맥스를 씁니다.
3. 결과는 **조언용**으로만 씁니다. 입력은 (라운드, 레벨, 골드, 체력, 연승)이고, 출력은 레벨업, 리롤, 저축 중 하나입니다. 이 결과를 coach와 TFT 선생님의 운영 판단 근거로 사용합니다. 실제 게임 입력을 자동화하는 데에는 쓰지 않습니다.
