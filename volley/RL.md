# 냥냥 배구 — 강화학습용 설명 (RL hooks)

규칙·물리는 전부 `core.js` 하나에 있고, 화면 없이 Node 에서 그대로 돌아갑니다.
브라우저에서는 `window.Volley`, Node 에서는 `require('./core.js')`.

```js
const V = require('./game/volley/core.js');
const s = V.create({ target: 11 }, 12345);          // 씨앗 하나로 경기 전체가 정해짐
while (s.phase !== 'over') {
  const a = V.actionToInput(myPolicy(V.obs(s, 0)), 0);  // 왼쪽 고양이
  const b = V.actionToInput(oppPolicy(V.obs(s, 1)), 1); // 오른쪽 고양이 (스스로를 왼쪽으로 보게 뒤집힌 관찰)
  const events = V.step(s, a, b);                   // 한 틱 (1/60초) 진행, 이번 틱에 일어난 일 목록
}
```

Node 속도: 무작위 입력 약 660만 틱/초, obs 두 번 포함 약 630만 틱/초, 고급 봇 둘이 두면 약 17만 틱/초 (이 PC 한 코어).

## 1. 상태 (JSON 그대로 저장·전송)

`V.create(opts, seed)` 가 돌려주는 평범한 객체. 배열·숫자·문자열뿐이라 `JSON.stringify` 로 저장하고 `V.fromJSON(text)` 로 되살리면 그대로 이어집니다.

| 필드 | 뜻 |
|---|---|
| `v` | 상태 모양 번호 (지금 1) |
| `tick` | 지난 틱 수 (60틱 = 1초) |
| `target` | 이기는 점수 (7 / 11 / 15) |
| `maxTouches` | 한 편이 넘기기 전 최대 터치 (0 = 제한 없음, 기본) |
| `rng` | mulberry32 씨앗 난수 상태 (첫 서버 정할 때만 씀) |
| `phase` | `ready` 서브 대기 · `play` 경기 중 · `point` 점수 뒤 쉬는 시간 · `over` 끝 |
| `phaseT` | 지금 단계에서 남은 틱 |
| `score` | `[왼쪽, 오른쪽]` |
| `server` | 다음 서버 (0 왼쪽 · 1 오른쪽, 점수 낸 쪽이 서브) |
| `winner` | 이긴 쪽 (끝나기 전엔 -1) |
| `touches`, `lastSide`, `lastTick` | 터치 세기용 |
| `ballSide` | 공이 지금 어느 쪽 코트 위에 있나 |
| `hits`, `crosses` | 이번 랠리의 접촉 수 · 그물 넘긴 수 |
| `lastHitter`, `lastKind` | 마지막으로 친 쪽 · 방법 (`bump` 몸으로 · `smash` 스매시 · `dig` 몸 날려 받기) |
| `stats` | 가장 긴 랠리 · 스매시 · 퍼펙트 · 다이빙 받기 수 |
| `lastPoint` | 마지막 점수 정보 |
| `cats[i]` | `x, y` 발 가운데 위치 · `vx, vy` · `ground` · `swing` 휘두르는 남은 틱 · `swingCd` 다시 휘두르기까지 · `dive` 몸 날리는 남은 틱 · `diveDir` · `rec` 일어나는 남은 틱 · `noHit` 연속 접촉 막기 · `dbuf` 방향 없이 스매시를 누른 뒤 방향키를 기다려 주는 남은 틱 · `prevIn` 지난 입력 |
| `ball` | `x, y, vx, vy` |

좌표: x 는 0(왼쪽 벽) ~ 640(오른쪽 벽), 그물은 x = 320 (높이 128 + 둥근 꼭대기 6). y 는 모래(0)에서 위로 +. 천장은 없음. 공 반지름 20, 고양이 몸은 세로 캡슐(반지름 34, 키 80). 상수는 `V.C`.

## 2. 입력 · 행동표

입력은 비트 6개 (`V.IN`): `LEFT 1 · RIGHT 2 · JUMP 4 · SMASH 8 · DOWN 16 · UP 32`. 방향은 **화면 기준**입니다. `V.bits({ left, right, jump, smash, down, up })` · `V.unbits(n)` 로 바꿀 수 있어요. `DOWN`·`UP` 은 공중 스매시 방향에만 쓰이고 움직임엔 영향이 없습니다.

- 점프는 누르고 있으면 높이, 일찍 떼면 낮게 뜁니다 (땅에서 누르고 있으면 착지하자마자 또 뜀).
- 스매시는 **누르는 순간**(앞 틱엔 안 눌림 → 이번 틱 눌림)만 동작: 공중이면 휘두르기(12틱, 앞 3틱 안에 맞으면 퍼펙트).
- **땅 스매시는 방향키를 누른 채일 때만 다이빙** (16틱 + 일어나기 16틱, 누른 쪽으로). 방향 없이 누르면 아무 일 없이 `swipe` 일만 나오고 한 칸도 안 움직입니다. 스매시를 먼저 누르고 방향키가 `DIVE_BUF`(4)틱 안에 오면 그래도 다이빙.
- 공중 스매시 방향은 **공이 앞발에 닿는 틱에 누르고 있는 키**로 정해집니다 (`V.aimOf(cat, side)`). 앞 = 상대 쪽(그물 쪽), 위 = `UP` 비트 **또는** `JUMP` 를 누른 채 (단 고양이 vy ≤ `UP_VY`(1), 즉 꼭대기를 지났을 때만 — 높이 뛰려고 누른 점프와 구분), 아래 = `DOWN`. 위·아래를 같이 누르면 둘 다 없는 것으로 봅니다.

| 누른 방향 | 이름 | 공 |
|---|---|---|
| 없음 | `power` | 곧고 힘찬 공 (속도 17.5, 28°부터 그물을 넘는 가장 가파른 각도) |
| 앞 | `drive` | 더 빠르고(19.5) 납작한 강타 |
| 위 | `lob` | 높이 띄워 살짝 넘기기 (그물 앞에서 치면 짧게, 멀리서 치면 길게) |
| 아래 | `spike` | 가장 가파르게 내리꽂기 (멀면 그물 때문에 저절로 납작해짐) |
| 앞+위 | `rise` | 오르다 상대 코트 깊이(그물에서 240) 떨어짐 |
| 앞+아래 | `dunk` | 내리꽂기보다 빠름 (19.6) |
| 뒤 | `back` | **제 코트 뒤쪽으로 높이** (벽에서 60 ~ 그물에서 50 사이, 100 뒤에 놓임). 0.8초 넘게 떠 있어서 달려가 받을 수 있음 → 2:2 에서 짝에게 올려 주기 |
| 뒤+위 | `set` | 더 높이(apex 220)·더 뒤로(150) |
| 뒤+아래 | `back` | `back` 과 같음 |

앞쪽 계열이 너무 낮아 그물을 못 넘으면 `lob` 으로 바뀝니다 (제 코트에 꽂지 않음). `hit` 일의 `aim` 이 실제로 나간 이름입니다.

학습용 행동표 `V.ACTIONS` (15가지) = `[방향, 점프, 스매시, 아래]`, 방향은 **자기 기준** (0 없음 · -1 뒤 · +1 앞=상대 쪽). 0~11 은 예전 그대로(아래 없음), 12~14 가 새로 생겼습니다:

| 번호 | 방향 | 점프 | 스매시 | | 번호 | 방향 | 점프 | 스매시 |
|---|---|---|---|---|---|---|---|---|
| 0 | 없음 | | | | 6 | 뒤 | ○ | |
| 1 | 없음 | | ○ | | 7 | 뒤 | ○ | ○ |
| 2 | 없음 | ○ | | | 8 | 앞 | | |
| 3 | 없음 | ○ | ○ | | 9 | 앞 | | ○ |
| 4 | 뒤 | | | | 10 | 앞 | ○ | |
| 5 | 뒤 | | ○ | | 11 | 앞 | ○ | ○ |

| 번호 | 방향 | 점프 | 스매시 | 아래 | 공중에서 나가는 것 |
|---|---|---|---|---|---|
| 12 | 없음 | | ○ | ○ | `spike` |
| 13 | 뒤 | | ○ | ○ | `back` |
| 14 | 앞 | | ○ | ○ | `dunk` |

예전 행동(0~11)으로 나가는 공: 1·5·9 = `power`·`back`·`drive` (땅이면 1 은 이제 헛손질), 3·7·11 = 점프 켠 채 스매시 — 꼭대기 근처 이후엔 점프가 '위'로 읽혀 `lob`·`set`·`rise`. `UP` 비트 단독 행동은 표에 없습니다 (사람 터치 입력·규칙 봇이 씀). 예전에 학습한 12 출력 정책은 그대로 동작합니다 (`policy()` 는 출력 길이만큼 고름).

`V.actionToInput(a, side)` 가 자기 기준 행동을 화면 기준 비트로 바꿔 줍니다 (오른쪽 고양이의 '앞'은 왼쪽). 사람 플레이 기록을 행동 번호로 바꾸려면 `V.inputToAction(bits, side)` (흉내 학습용, 아래+스매시는 12~14).

## 3. 관찰 obs (길이 18, Float32Array)

`V.obs(state, side, out?)` — **각자 자기가 왼쪽에 있는 것처럼 좌우를 뒤집어** 줍니다. 그래서 한 정책을 양쪽 모두에 그대로 쓸 수 있어요 (셀프플레이). 숨은 정보는 없는 게임이라 두 쪽 관찰은 같은 정보를 거울로 본 것입니다.

| 칸 | 값 | 대략 범위 |
|---|---|---|
| 0, 1 | 내 x (그물 기준, 내 쪽 -1~0), 내 y / 150 | -1~0, 0~1.2 |
| 2, 3 | 내 vx (앞이 +) / 6.2, 내 vy / 14.4 | -1.6~1.6, -1.3~1 |
| 4–7 | 상대 고양이 같은 4개 (상대 x 는 0~1) | |
| 8, 9 | 공 x (그물 기준), 공 y / 300 | -1~1, 0~3 |
| 10, 11 | 공 vx (앞이 +) / 20, 공 vy / 20 | -1.2~1.2 |
| 12 | 내가 휘두르는 중이면 1 | 0/1 |
| 13 | 다시 휘두르기까지 남은 비율 | 0~1 |
| 14 | 몸 날리는 중 남은 비율(+) / 일어나는 중(-) | -1~1 |
| 15 | 상대가 몸 날리거나 일어나는 중이면 1 | 0/1 |
| 16 | 내 터치 수 / maxTouches (제한 없으면 0) | 0~1 |
| 17 | 경기 중 1 · 서브 대기 중 -(남은 비율) · 그 밖 0 | -1~1 |

`selftest.js` 가 3,000틱 무작위 경기에서 모든 값이 유한하고 |값| ≤ 3 인지, 거울 상태의 반대편 obs 가 원래 obs 와 같은지 확인합니다.

## 4. step 이 돌려주는 일 (events)

`V.step(s, inA, inB)` 는 상태를 바꾸고, 그 틱에 일어난 일 배열을 돌려줍니다. 화면은 이것만 보고 소리·효과를 냅니다.

| `t` | 필드 | 뜻 |
|---|---|---|
| `jump` | side | 뛰어오름 |
| `land` | side, v, dive | 착지 (v = 떨어지던 속도) |
| `swing` | side | 공중 휘두르기 시작 |
| `dive` | side, dir | 몸 날리기 시작 |
| `swipe` | side, cat | 땅에서 방향 없이 스매시를 누름 (제자리 헛손질, 안 움직임) |
| `hit` | side, kind(bump/smash/dig), aim(power/drive/lob/spike/rise/dunk/back/set), perfect, x, y, v, vx, vy, n | 공에 닿음 (n = 이번 편 터치 수, vx·vy = 친 직후 공 속도 — 화면 화살표용) |
| `wall` · `net` | x, y, v | 벽·그물에 튕김 |
| `floor` | x, y, v, side, point | 모래에 닿음 (point = 이걸로 점수가 났나) |
| `fault` | side, reason | 터치 초과 (maxTouches > 0 일 때만) |
| `point` | w, reason, kind, final, score | 점수 (w = 점수 낸 쪽) |
| `serve` | side | 서브 (공이 톡 올라감) |
| `ready` | side | 다음 서브 대기 시작 (위치 되돌림) |
| `over` | w | 경기 끝 |

보상 예시: `point` 이벤트에서 `w === 내 쪽` 이면 +1, 아니면 -1. 처음엔 '공이 내 쪽 모래에 떨어지기까지 걸린 틱' 같은 모양 잡기(shaping)를 조금 더해도 됩니다. 한 판 = `over` 까지 (또는 틱 제한).

## 5. 결정성 (같은 씨앗 + 같은 입력 = 같은 결과)

- 코어 안에 `Math.random` · `Date` · `performance` · 삼각함수가 없습니다. 사칙연산과 `Math.sqrt` 만 써서 다른 언어(파이썬 float64)로 옮겨도 같은 값이 나옵니다. 스매시 각도도 cos/sin 값을 표로 박아 두었습니다 (`V.SPIKE_ANG`, `V.DRIVE_ANG`, `V.POWER_ANG` = SPIKE_ANG 의 뒷부분).
- 난수는 상태 안의 mulberry32 (`s.rng`) 하나뿐이고, 경기 시작 때 첫 서버를 정할 때만 씁니다.
- `V.hash(s)` (FNV-1a) 로 상태를 비교할 수 있고, selftest 가 씨앗 5개 × 6,000틱을 두 번 돌려 해시가 같은지, 중간에 JSON 으로 복사해도 같은지 확인합니다.
- 봇(`bots.js`)도 자기 씨앗 난수만 써서, 봇 씨앗까지 같으면 경기가 똑같이 재현됩니다.
- 좌우 대칭: `V.mirror(s)` 는 좌우를 뒤집은 상태를 만듭니다. 뒤집은 상태를 좌우 바꾼 입력으로 굴리면 계속 거울상이 됩니다 (데이터 두 배로 늘리기에 씀).
- 화면 쪽의 '멈칫'(스매시 때 잠깐 멈추는 효과)은 그림 시간만 멈출 뿐 코어 틱 순서에는 영향이 없습니다.

## 6. 학습한 정책 끼우기

게임 화면(`main.js`)은 각 편을 `ctl.input(state) → 입력 비트` 하나로 움직입니다. 사람 키보드·터치, 규칙 봇, 학습한 정책, (나중에) 친구 연결이 모두 같은 자리에 들어갑니다.

지금 바로 쓸 수 있는 자리: `VolleyBots.policy(brain, side)` — 작은 MLP 를 JSON 으로 받아 obs 18개 → 행동 중 가장 큰 것을 고릅니다 (출력 12개면 예전 행동, 15개면 아래 스매시까지).

```js
// brain = { layers: [{ W: [[...18개]...], b: [...], act: 'tanh' }, ..., { W, b, act: 'linear' }] }  (마지막 출력 12개 또는 15개)
const ai = VolleyBots.policy(brain, 1);
const input = ai.act(state);   // 오른쪽 고양이 입력 비트
```

새 AI 단계로 넣을 때는 `main.js` 의 `mkBot`(start 안) 옆에 `{ kind: 'policy', input: s => ai.act(s) }` 를 만들고 메뉴 카드(예: 👑 고수)를 하나 더하면 됩니다. 더 큰 모델은 onnxruntime-web 으로 같은 obs 를 넣으면 되고, 무거우면 Web Worker 에서 돌리세요 (지금 규칙 봇은 한 틱에 평균 수 µs, 최대 약 2ms 라서 워커 없이 돕니다).

규칙 봇(`bots.js`)은 학습 상대·시범 데이터로도 쓸 수 있습니다: 단계별 성격(반응 지연·자리 오차·스매시 의지·노림수·다이빙·쓰는 스매시 방향 `aims`)이 `VolleyBots.TIERS` 에 있고, 승률 순서는 고급 > 중급 > 초급 (selftest 가 확인). 쓰는 방향: 초급 `power·drive·lob` 중 아무거나 · 중급 `power·drive·spike·lob` 중 고르거나 아무거나(50%) · 고급 `power·drive·spike·dunk·lob·rise` 를 모두 재어 가장 좋은 것. 뒤로 스매시(`back`·`set`)는 안 씁니다. 봇은 땅 스매시를 다이빙할 방향키와 함께만 누르고, 휘두르는 동안엔 고른 방향 키만 누릅니다.

## 7. 2:2 복식 (`team: 2`)

```js
const s = V.create({ target: 11, team: 2 }, 12345);   // 고양이 넷: 0·2 왼쪽 편, 1·3 오른쪽 편 (V.sideOf(k) = k & 1)
V.step(s, in0, in1, in2, in3);                        // 입력도 고양이 번호 순서로 넷 (1:1 은 예전처럼 둘)
const o = V.obsTeam(s, k);                            // 고양이 k 기준 관찰 26개 (V.OBS_N2)
const a = V.actionToInput(act, V.sideOf(k));          // 행동표·방향 뒤집기는 편 기준 그대로
```

- 1:1 상태에는 복식 필드가 **하나도 없어서** 예전 저장값·학습 코드·해시가 그대로입니다. 복식일 때만 상태에 `team: 2`, `rot: [왼, 오]`(편마다 지금 뒤에 서는 고양이: 0 → 고양이 side, 1 → side+2), `serveCat`(이번 서버 고양이), `lastCat`(마지막으로 친 고양이)이 붙습니다.
- 자리: 점수마다 편마다 뒤 1마리(`D_BACK` 112) · 앞 1마리(`D_FRONT` 238). 서브는 서브 편의 뒤 고양이가 넣습니다.
- 서브 돌아가기: 서브를 **되찾은 편**만 한 칸 돕니다 (`rot ^= 1`). 그래서 서버는 0 → 1 → 2 → 3 → 0 … 순서로 넷이 돌아가고, 점수를 계속 내는 편은 같은 고양이가 계속 서브합니다.
- 같은 편끼리: 딱딱한 충돌 없이 겹치면 한 틱에 최대 `TM_PUSH`(1.6)씩 부드럽게 떼어 놓습니다 (`TM_SEP` 58 안, 위아래 `TM_DY` 70 안일 때만). 벽에 몰려도 끼지 않고, 위로 뛴 짝 밑으로는 지나갈 수 있습니다. 다른 편은 그물로 나뉘어 닿지 않습니다.
- 터치: 같은 편 **다른 고양이**가 받으면 붙어 있어도 새 터치 (같은 고양이만 `TOUCH_MERGE` 로 묶음). `maxTouches` 는 편 단위.
- 이벤트: `jump · land · swing · dive · hit · serve · ready` 에 `cat`(고양이 번호)이 붙습니다 (1:1 이면 cat = side). `point.w`, `over.w` 는 편 번호.
- `V.mirror(s)` 는 복식도 뒤집습니다 (고양이 0↔1, 2↔3).

`obsTeam(s, k)` (길이 26): 0~17 은 1:1 obs 와 같은 뜻인데 '나' = 고양이 k, '상대' = 맞은편 고양이 k^1 · 18~21 같은 편 짝 x, y, vx, vy · 22~25 다른 상대 x, y, vx, vy (모두 고양이 k 가 왼쪽에 있는 것처럼 뒤집힘). 거울 상태의 반대편 관찰과 같음을 selftest 가 확인합니다.

복식 봇: `VolleyBots.create(tier, side, seed, { cat: k, team })` — 같은 편 두 봇에 **같은 빈 객체 `team`** 을 주면 '누가 받을지'를 함께 봅니다. 이번 공(랠리·접촉 수·넘김 수가 같은 동안)은 공이 처음 받을 높이로 내려오는 곳까지 가까운 고양이가 맡고 (방금 친 고양이는 다음 터치를 짝에게 미룸), 다른 하나는 짝이 가려는 자리에서 90 이상 떨어진 앞(그물)이나 뒤를 지킵니다. 공이 상대 쪽에 있으면 그물에 더 가까운 쪽이 앞, 다른 쪽이 뒤 자리로 (넘김마다 한 번 정함).
